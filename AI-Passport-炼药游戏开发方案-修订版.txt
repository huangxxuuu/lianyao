# AI Passport 炼药游戏开发方案（修订版）

> 文档状态：方案评审稿，可交给 Codex / Claude Code 等开发 Agent 继续拆解，但本文件本身不要求立即开发。
> 目标：先做出可在真实 AI Passport 上完成“探索—采集—炼制—展示”闭环的 MVP，再逐步增加联网校时、社交发现与功耗优化。

---

## 1. 产品定义

### 1.1 名称

- 中文名：炼药通行证
- 英文名：Potion Passport
- 内部代号：`potion-passport`

### 1.2 一句话体验

玩家携带 AI Passport 在现实环境中发现 Wi-Fi 与 BLE“信号源”，靠近并采集由信号指纹决定的材料；回到自己登记的“炼药房”组合材料，解锁药剂，并在屏幕或近距离 BLE 展示给其他玩家。

### 1.3 核心体验原则

1. **现实环境参与生成**：不同地点有不同信号组合，探索会带来不同材料。
2. **玩家有明确选择**：雷达不会自动收走最强材料；玩家移动探索、选择材料并确认采集。
3. **结果可解释**：采集界面只显示材料、探测强度、冷却和可采状态，不暴露无线来源；炼制结果由材料属性、药剂规则和优先级稳定决定。
4. **离线也能完成主循环**：网络连接不是采集与炼制的前置条件。
5. **社交默认克制**：MVP 只在展示页广播，不持续后台跟踪，不广播玩家身份或原始地址。

### 1.4 MVP 完成标准

一台设备在没有手机配合、没有互联网连接的情况下，能够：

- 用无方向雷达显示附近最多 3 种材料，并在完成探索进度、靠近阈值和冷却检查后连续采集；
- 绑定炼药房时只扫描 Wi-Fi，并以真实 SSID 供玩家选择；
- 仓库只显示玩家实际拥有的材料；
- 断电重启后保留仓库、炼药房、药剂、最近配方和冷却状态；
- 在已登记炼药房附近向四格大锅投入材料，按属性规则和优先级炼制药剂或浑浊药剂；
- 在配方手册中查看每种已产出药剂最近 10 种不重复的成功组合；
- 在展示页显示药剂，并发出可被另一台同版本设备识别的 BLE 广播；
- 在射频失败、存储失败、时间无效等情况下给出可恢复提示，不黑屏、不死机。

### 1.5 MVP 明确不做

- 不承诺 BLE 随机地址跨天或跨地点保持稳定。
- 不做绝对方向或距离判断；RSSI 只提供“变强/稳定/变弱”的趋势。
- 不做后台常驻广播、排行榜、云账号、远程同步或防作弊系统。
- 不把路由器 SSID、BSSID、蓝牙地址或玩家身份明文写入广播。
- 不沿用仓库中的硬件测试菜单、测试页面或其视觉外壳。

## 2. 硬件与工程基线

### 2.1 已确认硬件

| 能力 | 基线 |
|---|---|
| 主控 | ESP32-C3，8 MB Flash，无 PSRAM |
| 屏幕 | ST7789P3，240×320 竖屏，RGB565 |
| 输入 | UP / DOWN / OK 三个按键，共用 GPIO0 的 ADC 电阻梯 |
| 音频 | ES8311，I2S0 全双工；播放/录音是阻塞操作，必须放到工作任务 |
| 电池 | CW2017，可读取电量；读取失败时 UI 应隐藏数值或显示未知状态 |
| 无线 | 2.4 GHz Wi-Fi + BLE，共用射频资源 |
| 定位/环境 | 无 GPS、陀螺仪、加速度计、磁力计和独立环境传感器 |
| 控制台 | ESP32-C3 原生 USB Serial/JTAG |

具体引脚、总线、地址和电压窗口只以 `components/bsp/include/bsp_pins.h` 为准，不在应用代码中重复定义。

### 2.2 必须遵守的运行约束

- LVGL 只能在 LVGL 上下文中访问；其它任务更新界面前必须持有 `bsp_lvgl_lock()`。
- 按键回调只投递轻量事件，不执行扫描、NVS 写入、音频或动画等待。
- Wi-Fi、BLE、存储和音频分别由工作任务处理，通过队列向应用状态机回报结果。
- 页面退出时，先取消任务/定时器/回调，再销毁对应 LVGL 对象。
- 默认在右上角显示电量；电量不可用时优雅降级。
- 中文界面必须生成包含本项目全部字形的字体子集，并验证每个控件实际使用了该字体。Montserrat 不含中文字形。

### 2.3 内存策略

原方案中“LVGL 内存池必须 ≥48 KB”的结论缺少当前固件实测，不应写成硬规则。正确做法是：

1. 以仓库默认配置为起点；
2. 先完成只有首页、扫描页和结果页的最小 UI；
3. 在真机记录启动后空闲堆、最大连续空闲块、扫描峰值和页面切换峰值；
4. 只有出现可复现的 LVGL 分配失败时才逐级增加内存池；
5. 增大 LVGL 池时同步检查 Wi-Fi/BLE 初始化仍有足够连续内存。

图片优先使用小尺寸 RGB565/RGB565A8 或程序绘制；材料和药剂图标先做 24～40 px 的有限图集。禁止为装饰长期保留整屏 240×320×2 字节缓冲。

## 3. 游戏循环与玩家目标

### 3.1 核心循环

```text
首页
 ├─ 出门探索 → 雷达建立基线 → 移动探索 → 靠近材料 → 连续采集
 ├─ 查看仅包含已拥有材料的仓库与属性详情
 ├─ 回到炼药房 → 四格大锅投料 → 属性规则判定 → 药剂入册
 ├─ 配方手册 → 已产出药剂 → 最近 10 种不重复配方
 └─ 药剂展示 → 近距离广播
```

### 3.2 玩家长期目标

- 收集全部材料图鉴；
- 发现全部药剂规则，并为每种药剂积累不同的有效配方；
- 炼出不同外观种子的药剂变体；
- 与附近玩家互相发现展示中的药剂。

### 3.3 玩家能控制的关键决策

- 在雷达列出的 2～3 种材料中选择探索目标；
- 是否继续移动和靠近以完成探索进度与采集条件；
- 选择哪四份材料投入大锅，同一种材料可重复；
- 是否承担未知组合产出浑浊药剂并消耗材料的风险；
- 在配方手册中复用或改进过去成功的组合；
- 是否在展示页开启 BLE 广播。

## 4. 信号发现、身份与隐私

### 4.1 射频事实与调度原则

Wi-Fi 与 BLE 共用 2.4 GHz 射频，但不能简单描述为“绝对无法同时工作”。ESP-IDF 具备共存机制，实际吞吐、延迟和内存开销取决于模式。为了让 MVP 行为确定、便于调试，应用层仍采用**单一射频所有者 + 串行窗口**。探索模式串行扫描两种来源：

```text
RADIO_OFF
  → WIFI_SCAN
  → RADIO_OFF（清理结果/让出资源）
  → BLE_SCAN
  → RADIO_OFF
```

炼药房登记和附近校验使用独立的 `LAB_WIFI_SCAN` 请求，只启动 Wi-Fi，不初始化或扫描 BLE。UI 和无线服务都不得把炼药房扫描复用为完整探索轮次。

不要把固定“Wi-Fi 3 秒 + BLE 2 秒”写死在 UI 线程中。扫描由事件驱动的无线工作任务执行，每一阶段有超时和取消令牌；页面退出后，旧扫描结果不得再更新已销毁页面。

### 4.2 扫描窗口建议

- Wi-Fi：一次主动扫描，记录 BSSID、信道、RSSI；探索页不显示 SSID，炼药房登记页临时显示真实 SSID。
- BLE：2～4 秒扫描窗口，按规范化指纹去重并保留峰值/平滑 RSSI。
- 每轮结束后只把排名靠前的有限条目（建议最多 8 个）交给 UI。
- 扫描页面停止、超时或进入后台时立即归还射频资源。
- 炼药房登记过滤空 SSID；同名网络可重复显示并通过信号强度区分，但不得显示 BSSID 或内部 ID。

具体扫描时长和共存配置必须通过真机日志与功耗测试决定，不预先强制 `CONFIG_ESP_COEX_SW_COEXIST_ENABLE`。

### 4.3 Wi-Fi 信号指纹

Wi-Fi 源的规范输入：

```text
wifi_fingerprint_input = "PP/WIFI/V1|" + 6 字节 BSSID
fingerprint64 = SHA-256(input) 的前 8 字节
```

- BSSID 只在当前扫描结果内短暂存在；NVS 保存 `fingerprint64`，不保存原始 BSSID/SSID。
- 隐藏网络可参与材料生成，但因为无法显示实际名称，不进入炼药房登记候选；本地管理地址也可参与材料生成，但 UI 不宣称其跨时间稳定。
- 忽略明显无效地址、全零地址和广播地址。

### 4.4 BLE 信号指纹

BLE 地址尤其 RPA 会变化，不能作为长期设备身份。按以下优先级生成指纹：

1. 有稳定 Service Data：使用服务 UUID + 规范化后的稳定字段；
2. 有 Manufacturer Data：使用 company ID + 去除已知动态字段后的内容；
3. 无稳定载荷：使用地址类型 + 当前地址，标记为“临时信号”。

```text
ble_fingerprint_input = "PP/BLE/V1|" + source_kind + normalized_payload
fingerprint64 = SHA-256(input) 的前 8 字节
```

降级到地址的条目只保证当前扫描会话内稳定，UI 应使用“漂泊信号”等视觉提示，不宣称两名玩家一定得到相同结果。连续扫描取众数只能减少瞬时抖动，不能解决 RPA 长期变化。

扫描时应过滤本游戏自己的展示广播，防止玩家把药剂广播反复当作材料源采集。

### 4.5 隐私边界

- 日志默认只打印截断指纹，不打印完整 BSSID、SSID、BLE 地址和完整广播载荷。炼药房候选 SSID 只存在于当前扫描结果和 UI 生命周期内。
- NVS 不保存附近设备的名称、SSID 或原始地址。
- 展示广播不包含用户名、设备序列号、炼药房信息或位置线索。
- “清除数据”应删除游戏命名空间内的仓库、图鉴、炼药房和设置，不执行整片 Flash 擦除。

## 5. 材料生成与稀有度

### 5.1 版本化输入

所有生成算法必须带协议/词库版本，避免升级后旧材料被无意重映射：

```text
digest = SHA-256(
    "POTION_PASSPORT" |
    algorithm_version |
    catalog_version |
    source_type |
    fingerprint64 |
    season_id
)
```

MVP 的 `season_id` 是固件中固定、可迁移的内容季编号，不依赖日期。这样离线设备即使没有可信时间，也能稳定得到同一材料。以后若增加限时赛季，应由明确的内容更新或可信校时驱动，而不是直接读取可能错误的系统日期。

### 5.2 稀有度映射

不要先对整个材料池直接取模，否则稀有度取决于材料数量和排列。先用摘要字节确定稀有度，再在对应稀有度子池中选择材料：

| 来源 | 普通 | 稀有 | 史诗 | 传说 |
|---|---:|---:|---:|---:|
| Wi-Fi | 72% | 23% | 4% | 1% |
| BLE 稳定载荷 | 55% | 32% | 11% | 2% |
| BLE 临时地址 | 70% | 25% | 5% | 0% |

概率是首轮调参值，不是硬件事实。抽样必须用固定宽度整数和稳定字节序；同版本、同输入必须得到完全一致结果。材料词库排序变化不得改变既有 ID。

### 5.3 采集条件

探索 UI 不显示 Wi-Fi、BLE、地址或指纹，而是先把信号稳定映射为材料，再按材料 ID 聚合。相同材料有多个来源时，代表来源按“可采集 → 正在靠近 → 冷却中”排序，同状态选择信号最强者。雷达最多显示 3 种不同材料，每项只显示材料名称、稀有度、探测强度和状态。

设备没有陀螺仪或加速度计，无法直接证明玩家发生了位移。MVP 使用“无线环境变化”形成探索进度，并明确把它描述为探索活跃度而非运动检测。采集需要同时满足：

1. 进入探索页后完成约 3 秒基线采样；
2. 目标在最近若干扫描窗口中持续出现；
3. 页面已停留至少 8～12 秒；
4. 目标或附近信号的累计 RSSI 变化达到初始建议值 10～15 dB，并覆盖至少 3 个有效窗口；
5. 平滑 RSSI 达到可采区间，最近 5 个样本中至少 3 个达标；
6. 来源不在冷却中，玩家按 OK 确认。

RSSI 使用 EMA 或中位数平滑，并采用滞回避免进度条在阈值附近闪烁。建议起始参数：

- 可见：`>-90 dBm`
- 可接近：`>-72 dBm`
- 可采：`>-62 dBm`，最近 5 个样本中至少 3 个达标
- 退出可采：跌到 `<-68 dBm`

这些数值必须在真机上用不同路由器、手机、佩戴姿态和真实行走轨迹校准。无线波动可能造成误判，因此最低停留时间、环境变化量和靠近阈值必须共同生效。UI 只能显示“探索中、继续靠近、可采集、冷却中”和探测强度，不显示来源类型、内部 ID、方向或米数。

采集成功后保持在雷达页：当前来源进入冷却，代表来源重新选择，雷达继续刷新，玩家可以连续探索与采集。

### 5.4 冷却与时间失效策略

冷却针对**信号指纹**，而不是材料 ID。一个材料可能来自多个信号源，各自有冷却记录。

建议首轮冷却：

| 稀有度 | 冷却 |
|---|---:|
| 普通 | 15 分钟 |
| 稀有 | 2 小时 |
| 史诗 | 12 小时 |
| 传说 | 48 小时 |

两周冷却会让首版难以验证，也容易使玩家忘记玩法，因此不进入 MVP。

设备没有可假定为永远可靠的断电时钟，时间模型必须显式区分：

- `TIME_VALID`：已通过可信来源校时，可正常计算冷却；
- `TIME_ESTIMATED`：基于上次可信时间和当前连续运行时间估算；
- `TIME_UNKNOWN`：完整断电或时间倒退后无法确认。

`TIME_UNKNOWN` 时不把记录误判为已冷却；允许采集从未见过的新信号，已有冷却条目显示“需校时”。后续版本可通过炼药房 Wi-Fi + SNTP 或手机伴侣校时。MVP 可把校时作为可选功能，不得让联网成为基本探索的前置条件。

## 6. 炼药房与炼制系统

### 6.1 炼药房登记

“登记炼药房”只执行 Wi-Fi 扫描。候选列表显示真实 SSID 和信号强度，不显示 BSSID、指纹或内部 ID；空 SSID 不进入候选。同名 SSID 可重复出现并通过强度区分。SSID 仅在当前扫描结果中短暂存在，确认后只保存所选网络的 `fingerprint64`，不保存名称、BSSID 或密码。

进入炼制页的条件：

- 已登记炼药房；
- 最近一次 Wi-Fi 扫描发现该指纹；
- RSSI 达到建议阈值（初值 `>-72 dBm`）。

设置页可以重新登记炼药房。更换炼药房不会清空材料和药剂。

### 6.2 配方设计

炼制参考《饥荒联机版》的料理锅：玩家向固定四格大锅投入四份材料，同一种材料可以重复。每种材料携带固定属性向量，首版使用八类非负整数属性，每项建议为 `0～3`：

```text
草木 | 矿物 | 光 | 暗 | 火 | 寒 | 雷 | 龙
```

炼制时对四份材料逐项求和。每种药剂定义最小值、最大值、禁止属性和优先级；候选必须满足全部规则，多个候选同时满足时取优先级最高者，优先级相同则按稳定药剂 ID 取最小者。规则和材料属性属于版本化内容，发布后不得静默改变旧 ID 的语义。

首轮规则示例：

| 药剂 | 条件示例 | 优先级 |
|---|---|---:|
| 微光药剂 | 光 ≥ 2，暗 = 0 | 10 |
| 清醒药剂 | 草木 ≥ 2，寒 ≥ 1，火 ≤ 1 | 20 |
| 守护药剂 | 矿物 ≥ 3，草木 ≥ 1 | 30 |
| 幸运药剂 | 雷 ≥ 2，光 ≥ 1，暗 ≤ 1 | 40 |
| 星夜药剂 | 暗 ≥ 2，光 ≥ 2，火 = 0 | 50 |
| 龙息药剂 | 龙 ≥ 3，火 ≥ 2，寒 = 0 | 100 |

未命中正式药剂规则时，四份材料仍被消耗并产出具有稳定 ID 的“浑浊药剂”。浑浊药剂是正式收藏产物：保存数量和外观、可进入展示广播，也记录最近 10 种不重复配方；UI 将其标记为普通稀有度的失败产物。

```text
recipe_key = sort_and_count(four_material_id[])
property_total = sum(material.property[])
base_potion = highest_priority_matching_rule(property_total) or MUDDY_POTION
appearance_seed = SHA-256("PP/APPEAR/V1" | base_potion_id | lab_fingerprint64) 前 4 字节
```

材料加入大锅时只进入临时选择，不立即扣库存。四格填满后才允许确认炼制；列表末尾提供“撤回一个”“清空大锅”和“开始炼制”。长按返回会丢弃临时选择但不损失材料。

### 6.3 配方手册

配方手册第一层只显示玩家曾产出的药剂，包括浑浊药剂。每项显示药剂名称、当前数量和已发现配方数。进入具体药剂后显示最近 10 种不同组合：

- 配方按材料 ID 排序并合并数量，材料放入顺序不影响去重；
- 相同组合再次产出同一种药剂时不新增，而是移动到第一位；
- 第 11 种不同组合写入时移除最早记录；
- 不依赖系统时间，用单调递增的存档 generation 表示最近顺序；
- 正式药剂和浑浊药剂遵守相同记录规则。

### 6.4 炼制事务

炼制必须按事务处理：

1. 在纯逻辑层校验炼药房、四格材料数量、属性规则、优先级和历史容量；
2. 生成包含扣料、药剂数量、外观种子和配方历史的新状态副本；
3. 一次性写入带版本和校验的持久化记录；
4. 写入成功后才播放成功动画并广播事件；
5. 写入失败则保留原材料，显示错误并允许重试。

动画、音效或页面切换失败不得造成重复扣料。

## 7. BLE 展示协议

### 7.1 MVP 广播策略

- 只在“药剂展示页”开启不可连接广播；离开页面立即停止。
- MVP 不做后台定时广播。反复启停广播的功耗与稳定性需先真机测量。
- 设置中提供“允许近距离展示”开关，默认开启但首次进入展示页给出说明。

### 7.2 数据格式

使用固定的自定义 128-bit Service UUID 和紧凑 Service Data；不要冒用 Bluetooth SIG 已分配的 16-bit UUID 或公司 ID。

建议业务数据：

| 字段 | 大小 | 说明 |
|---|---:|---|
| protocol_version | 1 B | 展示协议版本 |
| catalog_version | 1 B | 本地词库版本 |
| potion_id | 2 B | 药剂 ID，小端 |
| rarity_flags | 1 B | 稀有度和展示标志 |
| appearance_seed | 4 B | 外观变体 |

接收端遇到未知协议或词库版本时，显示“未知时代的药剂”，不崩溃、不错误反查。BLE 链路层已有 CRC；业务数据重点是边界检查、版本检查和长度检查。

### 7.3 附近展示发现

MVP 可先只完成“发送”。若同一版本加入接收功能，应放在独立“附近药剂”页面，短时扫描后显示最多 5 条，不在后台持续跟踪，也不记录对方地址。

## 8. 页面与三键交互

### 8.1 视觉方向

设计为“便携炼金手册”，采用深色纸张、铜色边框、瓶中液体和手绘符号；避免复用基线测试菜单。首页使用可滚动的六项入口：探索、材料仓库、炼药、配方手册、药剂展示、设置。右上角保留电量。

探索页使用无方向雷达：同心圆、扫描线、信号波纹和冷却进度由 LVGL 动态绘制；最多 3 个材料标记的角度由稳定哈希决定，仅作视觉排布，不表示真实方向。半径、亮度和动画速度表达探测强度。

炼药页中央展示大锅和四个槽位，下方显示玩家拥有且仍有可用数量的材料列表。属性图标用于材料详情和炼制结果解释，但不直接泄露尚未发现药剂的完整判定规则。

### 8.2 全局按键规则

- UP / DOWN：移动选择或切换卡片；列表首尾可循环，但危险确认页不循环。
- OK 短按：确认、进入、开始/停止当前动作。
- OK 长按（500 ms 事件）：返回上一级；首页长按无动作。
- 不使用 UP+DOWN 等组合键，因为三键共用 ADC，组合电压不属于既有稳定输入合同。
- 扫描、存储、音频进行中仍允许长按返回；返回动作发出取消请求并显示短暂“正在停止”。

### 8.3 页面清单

| 页面 | UP / DOWN | OK 短按 | OK 长按 |
|---|---|---|---|
| 启动/恢复 | 无 | 跳过非关键动画 | 无 |
| 首页列表 | 切换功能并滚动 | 进入功能 | 无 |
| 探索雷达 | 在最多 3 种材料间切换 | 达标时采集；未达标时查看原因 | 返回首页并停止扫描 |
| 采集反馈 | 继续选择材料 | 确认提示后继续探索 | 返回首页 |
| 仓库 | 只在已拥有材料间选择 | 查看材料属性详情 | 返回首页 |
| 炼药大锅 | 在材料、“撤回一个”“清空大锅”“开始炼制”间移动 | 添加材料或执行操作 | 放弃临时投料并返回首页 |
| 炼制确认 | 选择取消/炼制 | 执行所选项 | 返回大锅且不扣料 |
| 炼制结果 | 切换详情 | 进入展示 | 返回首页 |
| 配方手册药剂列表 | 选择已产出药剂 | 查看该药剂最近配方 | 返回首页 |
| 配方历史 | 选择最近 10 种不重复组合 | 查看材料与属性总值 | 返回药剂列表 |
| 展示 | 切换已拥有药剂 | 开/关本页广播 | 返回首页并停播 |
| 设置 | 选择项目 | 编辑/确认；登记炼药房时进入 Wi-Fi 列表 | 返回首页 |
| 炼药房 Wi-Fi 列表 | 选择真实 SSID | 绑定所选 Wi-Fi 指纹 | 返回设置 |
| 清除数据确认 | 默认选“取消” | 执行所选项 | 取消 |

### 8.4 状态反馈

每个异步动作必须有四类反馈：

- 进行中：动画 + 可取消提示；
- 成功：结果和下一步；
- 可恢复失败：原因 + 重试；
- 不可继续：回到安全页面，并停止对应无线/音频任务。

## 9. 软件架构与状态机

### 9.1 模块边界

```text
main/
  app_state.*          纯状态机/reducer，不依赖 LVGL/ESP-IDF
  app_events.*         输入、无线、存储、计时事件
  material_catalog.*   稳定 ID、稀有度和材料定义
  potion_catalog.*     药剂定义、属性判定规则和优先级
  recipe_history.*     四材料组合规范化、去重和最近 10 条历史
  signal_fingerprint.* 规范化与哈希，纯逻辑可测
  collection_rules.*   RSSI 平滑、探索进度、材料聚合和冷却判定
  player_store.*       固定容量数据模型与序列化
  radio_service.*      Wi-Fi/BLE 所有权和异步命令
  storage_service.*    NVS 工作任务
  audio_service.*      可选音效工作任务
  ui_*.c               全新应用页面

components/bsp/
  只复用现有显示、按键、音频、电池和共享总线接口；
  除非发现通用硬件能力缺口，否则不把游戏逻辑放入 BSP。
```

### 9.2 顶层应用状态

```text
BOOT → HOME
HOME → EXPLORE_BASELINE → WIFI_SCANNING → BLE_SCANNING → MATERIAL_RADAR
MATERIAL_RADAR → EXPLORE_PROGRESS → COLLECT_COMMIT → COLLECT_FEEDBACK → MATERIAL_RADAR
HOME → INVENTORY → MATERIAL_DETAIL
HOME → BREW_GUARD → CAULDRON_SELECT → BREW_CONFIRM → BREW_COMMIT → BREW_RESULT
HOME → RECIPE_POTIONS → RECIPE_HISTORY → RECIPE_DETAIL
HOME/BREW_RESULT → SHOWCASE
HOME → SETTINGS → LAB_WIFI_SCAN → LAB_WIFI_LIST → LAB_COMMIT
任意异步状态 → RECOVERABLE_ERROR → 上一个安全状态
```

### 9.3 射频状态

```text
OFF | WIFI_SCAN | WIFI_STA_TIME_SYNC | BLE_SCAN | BLE_ADVERTISE
```

MVP 任何时刻只允许一种应用级射频模式。模式切换由 `radio_service` 串行执行，并带 `request_id`/generation；过期回调只记录诊断，不更新当前状态。`LAB_WIFI_SCAN` 是业务请求类型，不新增并行射频状态；它在一次 `WIFI_SCAN` 完成后直接回到 `OFF`，不得继续进入 `BLE_SCAN`。

### 9.4 任务与队列

| 执行域 | 职责 |
|---|---|
| LVGL/UI | 渲染当前状态，把按键意图投递给应用队列 |
| App reducer | 顺序处理事件，决定状态转换与副作用命令 |
| Radio worker | Wi-Fi/BLE 初始化、扫描、广播、取消与资源清理 |
| Storage worker | NVS 读取、原子写入、迁移和错误回报 |
| Audio worker | 短音效播放，允许取消；MVP 可先不用麦克风 |

所有队列必须有固定长度和溢出策略。RSSI 更新允许合并/丢弃旧值；采集确认、扣料结果和存储失败不得丢弃。

## 10. 数据模型与持久化

### 10.1 稳定 ID

- 材料、药剂、配方 ID 一经发布不复用。
- 删除内容保留 tombstone 或迁移表。
- 名称、描述和图标可变化，ID 与语义不能静默变化。

### 10.2 建议数据结构

```c
typedef struct {
    uint16_t id;
    uint8_t rarity;
    uint8_t icon_id;
    uint8_t properties[8]; /* 草木、矿物、光、暗、火、寒、雷、龙 */
    uint32_t cooldown_sec;
    const char *name;
    const char *description;
} material_def_t;

typedef struct {
    uint16_t id;
    uint8_t rarity;
    uint8_t icon_id;
    uint8_t priority;
    const char *name;
    const char *description;
} potion_def_t;

typedef struct {
    uint8_t min_value[8];
    uint8_t max_value[8];
    uint8_t forbidden_mask;
} potion_rule_t;

typedef struct {
    uint16_t material_id;
    uint16_t count;
} inventory_slot_t;

typedef struct {
    uint64_t source_fingerprint;
    int64_t next_collect_epoch;
    uint32_t last_seen_boot;
    uint8_t source_type;
    uint8_t flags;
} source_cooldown_t;

typedef struct {
    uint16_t potion_id;
    uint16_t count;
    uint32_t appearance_seed;
    int64_t first_crafted_epoch;
} potion_entry_t;

typedef struct {
    uint16_t material_id[4]; /* 升序；重复 ID 表示重复材料 */
    uint32_t last_used_generation;
} recipe_history_entry_t;
```

`last_collect_ts` 不应放在材料库存项中，因为冷却属于信号源而不是材料。
`max_value` 使用 `UINT8_MAX` 表示该属性没有上限；`forbidden_mask` 中置位的属性总值必须为零。配方历史只保存规范化后的四个稳定材料 ID，不保存名称或 UI 顺序。

### 10.3 容量建议

- 材料定义：首版 24～32 种；库存按稳定 ID 的定长计数表保存。
- 药剂定义：首版 12～20 种；药剂册保存数量和最近/首次外观种子。
- 大锅：固定 4 个临时槽位，不写入 NVS；只有炼制事务成功后才扣库存。
- 配方历史：每种已产出药剂最多 10 条不同的四材料组合；浑浊药剂使用相同容量。
- 冷却记录：最多 96 或 128 条。优先清除已过期且最久未见的记录；未过期记录不得静默淘汰，否则可绕过冷却。
- 扫描结果：UI 最多 8 条；无线任务内部也设置硬上限。

### 10.4 NVS 记录

使用独立命名空间，例如 `potion_game`：

```text
meta_a / meta_b       双槽元数据：magic、schema、generation、CRC
inventory_a / _b     双槽库存
potions_a / _b       双槽药剂册
recipes_a / _b       每种药剂最近 10 种去重配方
cooldowns_a / _b     双槽冷却表
settings_a / _b      炼药房指纹、广播开关、时间状态
```

每次事务写入非活动槽，校验成功后更新 generation。启动时选择 generation 最大且 CRC 正确的一组；单组损坏时回退，不立即清空所有数据。只有实际状态变化才写 NVS，避免每个 RSSI 样本或动画帧写 Flash。

### 10.5 迁移和恢复

- `schema_version` 管数据结构迁移；`catalog_version` 管内容兼容。
- 从旧 schema 升级时保留库存、药剂数量、冷却和炼药房指纹；旧版本无法推导历史配方，因此迁移后历史为空。
- 新固件必须读取旧 schema 或明确显示“数据版本不兼容”，不能静默解释成新结构。
- 清除数据有两次 UI 确认，只清本应用命名空间。
- 存储初始化失败时进入只读体验或错误页，不继续假装保存成功。

## 11. 中文字体、美术与音效

### 11.1 字体

- 在方案冻结后导出所有中文 UI、材料名、药剂名、错误文本的字符清单。
- 生成 1～2 个字号的字体子集，避免整套 CJK 字体占用 Flash。
- 动态名称必须来自内置词库；若接收未知版本的广播，使用本地已覆盖的通用文本。
- 真机逐页检查缺字方框、截断、基线和长名称换行。

### 11.2 美术

- 现有材料和正式药剂图标继续复用；新增大锅、浑浊药剂、配方手册、八种属性、雷达中心和采集状态图标。
- 雷达同心圆、扫描线、信号波纹、冷却进度、四个槽位和选中边框优先用 LVGL 程序绘制，以便动态变化并节省 Flash。
- 稀有度不能只靠颜色区分，同时使用边框形状、星数或符号。
- 关键文本字号优先保证佩戴/手持距离可读。

生成任何新图前，先把统一主提示词保存到仓库。提示词固定：复古掌机像素风、便携炼金手册主题、深紫/铜金/青绿配色、硬边像素、无抗锯齿、正面或轻微俯视、透明背景、无文字/数字/水印、统一光源/像素密度/描边，并要求缩小后仍能辨认。

建议图集：

| 图集 | 单格尺寸 | 内容 |
|---|---:|---|
| `brewing-atlas` | 96×80 | 大锅和炼制状态 |
| `muddy-potion-atlas` | 48×48 | 浑浊药剂外观变体 |
| `property-icons-atlas` | 24×24 | 草木、矿物、光、暗、火、寒、雷、龙 |
| `navigation-icons-atlas` | 40×40 | 配方手册、雷达等入口图标 |
| `radar-status-atlas` | 20×20 | 可采集、冷却中、继续靠近 |

生成后必须检查透明背景、网格切分和像素边缘，使用最近邻缩放到实际尺寸，转换为 LVGL 可用的 RGB565A8，并生成整套预览图。真机验收需检查小尺寸轮廓、颜色、透明边缘和 Flash 增量。素材来源、生成提示词和处理脚本必须可追溯。

### 11.3 音效

MVP 可使用短合成提示音：锁定目标、采集成功、炼制成功、失败。音频调用在 worker 中执行；离开页面时可取消。麦克风互动延后，避免首版同时承担录音、无线和 UI 的内存峰值。

## 12. 错误与边界场景

| 场景 | 预期行为 |
|---|---|
| Wi-Fi 初始化/扫描失败 | 释放 Wi-Fi，显示重试；BLE 阶段可继续或整轮取消，由错误类型决定 |
| BLE 初始化/扫描失败 | 释放 BLE，保留 Wi-Fi 结果并标记 BLE 暂不可用 |
| 页面退出时扫描仍在运行 | 发取消命令；过期回调不得访问旧页面 |
| 结果在列表刷新时消失 | 保留目标短暂宽限，超时后回到列表，不自动换目标 |
| RSSI 在阈值附近抖动 | 平滑 + 滞回 + 多样本确认 |
| 玩家原地不动且无线环境稳定 | 探索进度不完成；提示移动探索，不把停留时间单独当作移动证据 |
| 无线环境自身波动 | 最低探索时间、累计变化量和靠近阈值共同判定；UI 不宣称检测到了真实移动 |
| BLE 地址变化 | 降级为临时信号；不承诺长期一致 |
| 时间未知/倒退 | 新信号仍可探索；已有冷却不自动解锁，提示校时 |
| NVS 满/写失败 | 不扣材料、不增加药剂；提示重试或清理 |
| 冷却表已满 | 只淘汰已过期记录；否则拒绝新增并给出维护提示 |
| 未登记/未发现炼药房 | 炼制页说明登记或靠近方式，不进入扣料流程 |
| 炼药房扫描发现隐藏网络 | 不列入候选；不显示无法验证的伪名称 |
| 四份材料不匹配正式药剂 | 消耗材料并产出浑浊药剂，同时更新数量、外观和去重配方历史 |
| 配方历史已满 | 新的不同配方移到第一位并删除最早一条；重复配方只更新最近顺序 |
| 广播开启失败 | 展示页仍可看药剂，明确显示“未广播” |
| 收到未知协议/词库版本 | 显示通用未知药剂，不解析越界 |
| 电量不可用 | 隐藏百分比或显示 `--`，不阻塞游戏 |

## 13. 测试与验收

### 13.1 主机自动测试

纯逻辑模块不依赖 ESP-IDF/LVGL，至少覆盖：

- 指纹规范化、字节序和固定测试向量；
- 同版本同输入结果稳定，版本变化按预期隔离；
- 稀有度边界和材料子池选择；
- RSSI EMA/中位数、滞回、基线采样、最低探索时间、累计变化量和多样本采集条件；
- 材料聚合、最多 3 种雷达目标、代表来源优先级和采集后继续探索；
- 冷却在有效、估算、未知、倒退时间下的行为；
- 炼药房请求只扫描 Wi-Fi，SSID UTF-8/截断/同名/隐藏网络处理，并验证 SSID 不持久化、不输出日志；
- 仓库只返回拥有数量大于零的材料；
- 四材料属性求和、最小值、最大值、禁止属性、优先级、稳定 ID 决胜和 appearance seed；
- 浑浊药剂产出、计数、展示及配方记录；
- 配方顺序规范化、重复移动到首位和每种药剂最近 10 条容量；
- 状态机取消、过期 request_id、错误恢复；
- 库存上限、冷却表淘汰规则和事务失败不扣料；
- 序列化、CRC、双槽回退和 schema 迁移；
- BLE payload 长度、未知版本和截断输入。

### 13.2 固件构建门禁

- 使用 ESP-IDF 5.5.3；
- 运行仓库完整验证门禁；
- 生成并验证从 `0x0` 刷写的 `build/FoloToy-AI-Passport-full.bin`；
- 确认目标为 ESP32-C3、8 MB Flash、无 PSRAM、USB Serial/JTAG 控制台；
- 记录固件大小、空闲分区、ELF/MAP 和完整镜像 SHA-256。

### 13.3 真机验收矩阵

至少使用两种路由器/热点、两种 BLE 广播源和两台 AI Passport（若验证社交协议）：

1. 冷启动、连续运行 30 分钟、反复进出扫描页无崩溃；
2. Wi-Fi/BLE 扫描失败后能恢复并再次扫描；炼药房登记全程不启动 BLE；
3. 同一 Wi-Fi 指纹在同版本设备上产生相同材料；
4. BLE 稳定载荷一致时材料一致，RPA 降级提示正确；
5. 雷达在不同朝向下不宣称方向或距离；原地稳定信号不能立即采集，真实移动后能在合理时间完成探索进度；
6. 页面退出后没有幽灵更新、看门狗或已删除对象访问；
7. 采集、炼制后立即断电，重启数据为完整旧状态或完整新状态；
8. 四格大锅支持重复材料、撤回和清空；炼制写入失败时材料未丢失；
9. 展示广播可被同版本设备解析，离开展示页后停止；
10. 未知/畸形广播不会崩溃；
11. 中文逐页无缺字，SSID、材料名、属性、配方和长名称不越界；
12. Wi-Fi/BLE 峰值期间记录空闲堆、最大连续块和任务栈余量；
13. 记录扫描、展示广播和待机三种状态的电流，决定是否进入后台广播阶段；
14. 每种药剂第 11 个不同配方淘汰最早记录，重复配方不增加条目；浑浊药剂遵守同一规则；
15. 大锅、浑浊药剂、属性和雷达状态图标在真机尺寸下轮廓清楚、透明边缘无杂色。

## 14. 分阶段路线图

### 阶段 0：需求冻结与技术探针

- [ ] 确定 24～32 种材料、12～20 种药剂与首批配方
- [ ] 冻结八类材料属性、各材料属性值、药剂阈值规则和优先级
- [ ] 冻结稳定 ID、算法版本、词库版本和自定义 128-bit UUID
- [ ] 单独验证 Wi-Fi 扫描、BLE 扫描、展示广播的初始化/停止/重复进入
- [ ] 真机测量无线峰值内存与基础功耗
- [ ] 确认中文字符清单和字体授权
- [ ] 保存统一像素美术主提示词，生成并检查大锅、浑浊药剂、属性、导航和雷达状态图集

交付：技术探针报告和可用内存/功耗基线，不做完整游戏 UI。

### 阶段 1：纯逻辑纵切

- [ ] 状态机、指纹、材料生成、探索进度、属性炼制、配方历史、库存和序列化
- [ ] 固定测试向量和主机测试
- [ ] 定义无线/存储服务接口，不接真实 UI

交付：主机测试通过的游戏核心。

### 阶段 2：可玩的离线 MVP

- [ ] 全新首页、无方向雷达、连续采集、仅已拥有材料仓库页面
- [ ] 串行 Wi-Fi/BLE 扫描与取消
- [ ] NVS 双槽持久化
- [ ] 仅 Wi-Fi 的炼药房登记与真实 SSID 临时显示
- [ ] 四格大锅、属性规则、浑浊药剂、药剂册和最近 10 条去重配方手册
- [ ] 中文字体子集、生成图集、动态雷达绘制和短音效

交付：单机完成探索—炼制闭环的合并固件。

### 阶段 3：近距离展示

- [ ] 自定义 Service Data 广播
- [ ] 展示页发送与“附近药剂”短时接收
- [ ] 协议版本兼容和畸形包测试
- [ ] 双机真机验收

交付：两台设备可互相发现药剂，不交换个人身份。

### 阶段 4：时间与赛季（可选）

- [ ] 炼药房 Wi-Fi 配网/连接或手机伴侣校时方案
- [ ] SNTP 时间状态机、断电后时间失效策略
- [ ] 版本化赛季迁移，不重映射旧收藏

交付：可信冷却和可控的限时内容。

### 阶段 5：功耗与后台能力（有测量后再决定）

- [ ] 比较持续低频广播与周期启停广播的功耗/稳定性
- [ ] 明确玩家开关、低电量自动关闭和退出清理
- [ ] 评估轻睡眠/深睡眠与 ADC 按键唤醒限制

只有测量表明收益合理且不会破坏主循环时，才加入后台广播。

## 15. 交给开发 Agent 的执行提示词

```text
请基于当前完整 FoloToy AI Passport 仓库实现《炼药通行证》，先阅读 AGENTS.md、
docs/development/ai-guide.md 及任务路由要求，并使用仓库已安装的 passport-* Skills。

以本方案的“离线 MVP”为第一交付范围：完成全新的应用 UI、串行 Wi-Fi/BLE 探索、
无方向材料雷达、基于无线环境变化的探索进度和连续采集、仅已拥有材料仓库、只扫描 Wi-Fi
并临时显示真实 SSID 的炼药房登记、四格大锅与材料属性/药剂规则/优先级判定、浑浊药剂、
每种药剂最近 10 种去重配方、NVS 双槽持久化和药剂展示页。不要复用基线 demo 菜单或测试页面。
```

## 16. 仍需产品方确认的内容

以下问题不阻塞方案整理，但应在开发阶段 0 冻结：

1. 材料与药剂的最终数量、命名、属性值、规则阈值和优先级；
2. 稀有度是否保留四档，还是简化为三档；
3. 真机射频测试后采用的探索进度、信号接近和可采集阈值；
4. 炼药房在后续版本中是否需要联网校时；
5. 临时 BLE 信号能否产出高稀有度材料；
6. 是否需要声音，以及安静模式的默认值；
7. 两台设备互相发现药剂是否属于首发范围；
8. 数据清除、版本升级和赛季迁移时希望保留哪些收藏。

以下设计已确定，不再作为待确认项：炼药固定投入四份材料且允许重复；未命中正式药剂规则时消耗全部材料并产出浑浊药剂；浑浊药剂纳入收藏、展示和最近 10 种去重配方记录；炼药房登记只扫描 Wi-Fi 并临时显示真实 SSID；探索界面不显示 Wi-Fi、BLE、SSID、BSSID、地址或内部 ID；材料仓库只显示玩家拥有的材料；新增素材遵循本方案定义的统一像素美术主提示词。

在尚未冻结的内容确定前，开发可以先做射频技术探针、纯逻辑测试和可替换的数据表结构，但不应提前锁死最终内容数值或长期迁移策略。
